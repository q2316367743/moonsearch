## Context

S10 要修复的是实际行为缺口：当前 `--live --engine scan` 会先完整扫描并物化 `Store`，随后才匹配输出；默认引擎仍是 `scan`；`--stats -n 1` 把截断后的输出数当成总命中数；stdout 的 EPIPE 和 SIGINT 130 没有项目级验证。目标是在保持现有查询语义、规范排序和原始字节输出不变的前提下，实现真正的 live 流式路径、准确诊断及可靠的管道/信号退出。

## 推荐实现方案

### 1. 建立可复用的 EntryView 与编译谓词

- 在 `src/exec/compile.mbt`、`predicate.mbt` 中引入统一的 `EntryView`，至少包含 `path/name/kind/size/mtime/flags/depth/parent_path` 和目录聚合信息。
- Store scan 通过 adapter 从现有 `Store + EntryRef` 构造 view；live scan 直接使用 Scanner 元数据。两条路径继续复用同一个 `compile_query`，避免语义分叉。
- 暴露“是否需要目录后序统计”的判断。涉及 `size:`、`childcount:`、`childfilecount:`、`childfoldercount:`、`empty:` 的 live 查询回退现有完整 Store 路径，因为文件夹大小/子项数在遍历当时尚不可知。
- 复用 `@util.cmp_paths`、日期解析、glob/regex、kind/visibility 和现有 `FormatTemplate`，不另写查询或格式化规则。

### 2. 实现规范顺序的可取消 live 遍历

- 保留 `src/index/scanner.mbt` 的 `scan()` 作为完整建库包装，新增独立 `scan_stream/scan_with`。
- 新遍历使用按 `(name, path)` 排序的目录 frontier，而不是直接 DFS 输出，以保证 live 输出与 `Store` 的规范顺序一致。
- 每条 Scanner 元数据先经过排除、hidden、one-file-system、名称长度等现有规则，再交给 CLI 注入的 visitor；visitor 可返回 `Continue/Stop`。
- 达到普通输出的 `--limit` 后立即停止后续目录列举和条目处理；`limit=0` 全量遍历。
- 在目录列举和条目处理处加入异步让出点，使 SIGINT 能被运行时及时处理。
- `WalkReport` 保留已观察的 `issues/skipped_*`，并记录 `directories_listed`、`entries_seen`、`entries_evaluated`、`predicate_evaluations`、`matches_found`、`emitted`、`stopped_early`。
- `--engine bitmap --live` 继续完整扫描后构建内存 Index，但保留报告供 `--verbose` 使用，并明确文档中的内存代价。

### 3. 接通真正的流式 stdout

- 在 `src/cli/run.mbt` 增加供可执行入口使用的流式运行入口；现有 `@cli.run` 保留，进程内测试仍可收集字节。
- `run_search` 对可流式的 `--live --engine scan` 逐条格式化并写入 sink，不再先返回完整 `Bytes`。
- 默认路径、basename、模板和 NUL 均按单条记录输出，保持原始字节与终止符语义。
- JSON 或模板 `{size}` 在目录大小未知时回退完整 Store；`--reverse`、`--folders-first` 和非 name 排序也回退现有完整求值路径，确保结果正确。
- 流式路径返回独立的“stdout 已写”结果形态，避免入口重复输出。

### 4. 默认引擎与诊断

- `src/cli/spec.mbt` 与 `engine_of` 的 fallback 同时改为 `bitmap`；配置文件仍可覆盖，CLI 仍最高优先。
- 将总命中数、候选数、输出数、Ids 形态分离：
  - bitmap 使用最终 `Ids::cardinality()` 作为总命中数，并输出 `sorted`/`bitmap` 形态；
  - scan 输出实际谓词求值次数作为候选数；
  - bitmap 在 plan 求值中统计 Scan/Trigram 实际候选检查次数。
- `--stats` 请求准确诊断时禁用 limit 早停：普通 live 仍达到 limit 即停止；带 `--stats` 时继续遍历计数，但只输出前 N 条。
- `--explain` 复用已编译结果，避免二次编译造成日期边界不一致；bitmap 保留基数、候选来源和降级原因，scan 标明 universe 来源与 `scan-engine` 原因。
- `--verbose` 输出 live 已观察的 skipped 计数和 issues；早停时文档明确这是部分扫描报告。

### 5. EPIPE 与 SIGINT

- 在 `cmd/moonsearch/main.mbt` 捕获 stdout 写入错误：EPIPE（Unix errno 32，Windows `ERROR_BROKEN_PIPE` 109）安静退出 0，不打印 stats/verbose；其他 stdout IO 错误仍退出 2。
- 流式写入遇到 EPIPE 时停止扫描并走同一安静退出路径。
- 不新增自定义 C signal handler，采用 MoonBit async runtime 现有 SIGINT 取消并重发信号约定；用真实子进程测试验证 shell 状态 `128+SIGINT=130`，同时记录直接 `waitpid` 为 `-SIGINT` 的系统语义。
- 在 Scanner 的同步 FFI 循环之间加入让出点，避免长扫描无法及时响应中断。

## 测试与验收

1. **live 早停计数**：扩展 `FakeSource` 的 list/stat 计数，构造后续 sentinel 目录；`-n 1` 后断言 sentinel 未被访问、求值次数精确、`stopped_early=true`，`-n 0` 全量访问。
2. **顺序与语义对拍**：live scan 与完整 Store scan、persisted bitmap 对拍默认/反向/limit/类型/正则/非法字节等路径；所有原先隐含 scan 的测试显式加 `--engine scan`。
3. **诊断**：至少 3 个命中时验证 `--stats -n 1` stdout 仅 1 条、stderr `matches: 3`，并验证 candidates、Ids 形态、explain 来源/降级原因。
4. **默认引擎**：help golden 显示 bitmap；用 explain 计划形状证明默认 search/count 走 bitmap，并验证配置 scan 与 CLI 覆盖。
5. **EPIPE**：真实进程关闭读端及 `| head -n1`，断言 producer stderr 为空、退出 0；`/dev/full` 验证非 EPIPE 仍退出 2。
6. **SIGINT**：对仍在运行的子进程发送 SIGINT，验证 shell 退出码 130、无 runtime fatal；Windows 平台跳过 Unix 信号测试。
7. **文档同步**：更新 `README.mbt.md`、`docs/modules/cli.md`、`index.md`、`exec.md`、`docs/configuration.md` 和 help/golden，说明流式写法、stats 全量口径、部分 verbose 报告、EPIPE 0 与 SIGINT 130。
