| 项目 | 内容 |
| --- | --- |

| 审查日期 | 2026-11-25 |
| 目标 | 补齐 `MIGRATION_PLAN.md` 中尚未满足的 P0、正确性、安全性与验收要求 |

| 当前状态 | S01–S10 已完成并通过验收；S11–S12 待实施 |

## 1. 总体原则

1. **先修正确性，再补功能，最后做性能与材料。**
2. 任何查询层改动都必须扩展扫描/位图两引擎差分语料。
3. 任何持久化格式改动都必须同步更新 `docs/db-format.md`、布局断言、golden/往返测试和损坏输入测试。
4. 每一步结束前至少运行：
   - `moon check --target native --deny-warn`
   - `moon build --target native`
   - `moon test --target native`
   - `moon testcli test tests/cli.md --target native`
   - `moon fmt --check`
   - `moon info` 后确认 `git diff` 与 `git status` 干净
5. 不得复制 FSearch 代码、注释、常量表或测试文本；只迁移公开语义。
6. 本计划不把以下明确延后的项目列为欠账：Unicode casefold/NFD、libmagic、PCRE2、路径 trigram、watcher 增量监控、GUI、Windows MFT/USN 与 Windows 路径语义。

## S01：修复查询正确性与语义边界

### 目标

让扫描与位图引擎对合法/非法查询的行为完全一致，修复嵌套根 `parent:` 漏报，并补齐计划中已经明确的查询语义。

### 主要改动

1. 编译与错误：
   - 在 `src/exec/plan.mbt` 中将“语义校验”与“Domain::Never 空集优化”分离。
   - 保证优化前校验所有叶子，非法正则/日期不能因域剪枝而被隐藏。
   - CLI 统一捕获解析期与编译期 `QueryError`。
   - `--compat` 对非法正则、日期、数值等延迟错误统一返回空集。
2. 嵌套根：
   - `ParentPaths` 改为“路径 → 多个 id”或直接返回 `Ids`。
   - `Ranges::parent_ids` 对同路径的所有父桶求并集。
   - 删除“合法 Store 中路径必然唯一”的假设，使用稳定 tie-break。
3. 数值、日期与 glob：
   - 支持 `field:==value` 与 `field: = = value`。
   - 支持 `past` 日期前缀。
   - 保留 glob 中转义的字面量 `*`/`?`。
   - `?` 匹配一个 Unicode 标量，并保留 ASCII 快路径。
4. 正则、flags 与类型：
   - `--regex` 应用 term 级自动路径/大小写规则。
   - 补全非 ASCII 大写字母检测。
   - `--type` 作为不可被查询修饰符覆盖的全局约束。
   - 文档化正则引擎支持的语法子集。
   - 明确自定义宏与普通 term 的修饰符作用域。

### 验收标准

- 以下查询在 scan/bitmap 下 stdout、stderr、退出码一致：
  - `file:regex:"[" folder:`
  - `file:dm:nonsense folder:`
  - 嵌套根下的 `parent:/r/sub`
- 不加 `--compat` 时非法查询退出码为 2；加 `--compat` 时按空集处理。
- `size:==5`、`dm:pastweek`、`index\*`、`--type file folder:` 均有符合计划的断言。
- Unicode `?` 覆盖 ASCII、多字节标量与非法字节。
- 差分语料新增非法查询、compat、嵌套根和转义矩阵。

## S02：建立字节安全扫描与原始字节输出

### 目标

让 Unix 任意字节文件名从扫描、索引、持久化到输出都保持字节一致；JSON 合法且有明确告警。

### 主要改动

1. 字节扫描：
   - 新增 `src/platform/posix`（或等价包），用最小 native stub 实现 `opendir`、`readdir`、`fstatat(AT_SYMLINK_NOFOLLOW)`、`closedir`。
   - `readdir` 通过 `(ptr, len)` 复制名字，不做 UTF-8 解码。
   - `NodeInfo.name`、`ScanSource`、`RootSpec`、`RootInfo.path` 改为字节表示。
   - `Builder::add_name` 接受 `BytesView`，Scanner 不再编解码名字。
   - 根路径按字节保存，DB ROOTS 格式同步调整。
2. 字节输出：
   - `src/exec/format.mbt` 返回 `Bytes` 或字节片段。
   - `CliResult` 与 `cmd/moonsearch/main.mbt` 直接写字节。
   - 默认路径、basename、模板、NUL、`--relative-to` 保留原始字节。
   - JSON 使用合法 UTF-8；非法字节以替换字符输出，并向 stderr 发出稳定告警。

### 验收标准

- 非法 UTF-8 名称 scan → NamePool → DB → load → match → 默认输出全链路字节一致。
- 两个不同非法名字不会折叠成同一替换字符串。
- NUL 输出每条恰好一个 `\0`，不额外添加换行。
- JSON 可被标准解析器解析且 stderr 有告警。
- 根 `/`、尾斜杠、`//`、深层路径测试通过。
- 现有 CLI golden 不回归；文档不再声称生产后端 lossy 处理名字。

## S07：加固 DB 校验与资源边界

### 目标

确保截断、附加尾部、损坏长度和恶意大集合不会逃过校验或先触发不受控分配。

### 主要改动

- 要求 CHECKSUM 是最后一个 section，且结束位置等于 EOF。
- `verify=true` 覆盖全部文件字节；未知 section 只能出现在 CHECKSUM 之前。
- 默认 metadata CRC 覆盖 roots/excludes 元数据，或同步修改文档明确新边界。
- 读取文件前检查大小上限，避免验证 2 GiB 上限前整文件读入。
- `DbReader::ensure` 使用减法/剩余长度判断，避免 `pos + count` 溢出。
- Ids codec 在分配/展开前校验声明基数、block 范围和容器数量。
- `validate_ids` 先检查 `cardinality <= total` 与最大 block，再展开 id。
- 为解码过程增加可测试的内存/操作预算。

### 验收标准

- 合法 DB 后追加任意字节，`verify=true` 必须拒绝。
- CHECKSUM 放在中间、后续存在 section 时必须拒绝。
- 超大长度、超大 block、声明基数超过 total 均在有限资源内返回 `DbError`。
- 原有逐截断、逐字节翻转、随机变异测试全部通过。
- `info --verify` 不再把未覆盖尾部报告为 verified。

### 涉及文件
